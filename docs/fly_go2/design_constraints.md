# Design Constraints: FlyWire MB on Unitree Go2

Спецификация гибрида: **урезанный коннектом грибовидного тела Drosophila (FlyWire FAFB)** как индивидуальный контроллер выбора действия на Go2; внешняя система только задаёт условия среды и анализирует результаты.

Связанные артефакты:
- `artifacts/connectome_mb_v1.npz` — рабочий MB-подграф FlyWire FAFB-783
- `artifacts/manifest.json` — counts, источники, sha256
- `docs/fly_go2/physical_setup.md` — физические условия и оборудование
- `docs/fly_go2/CITATIONS.md` — цитирование данных
- `configs/examples/episode.schema.yaml` — поля конфига эпизода
- `configs/examples/room_v1.yaml` — пример арены
- `configs/examples/agent_local.yaml` — локальные флаги особи

---

## 1. Неизменяемые принципы

### 1.1 Individuum-first sociality

Социальное поведение **формируется только внутри особи**:
- восприятие других агентов — через **собственные** сенсоры (камера, лидар, IMU);
- ассоциации и пластичность — только в локальном графе (`W_kc_mbon` + DAN-маски из коннектома);
- решение действия (`Approach` / `Avoid` / `Freeze` / `Explore`) — только локальный MBON-decode.

Внешняя система **не является** социальным мозгом, учителем чужих наград и шиной поведения между роботами.

### 1.2 External = conditions + analysis

| Внешнее (arena PC) | Индивидуум (Go2) |
|---|---|
| Карта зон, стимулы, лимиты safety | FlyWire MB subgraph + пластичность |
| Старт/стоп эпизода, e-stop | Локальный расчёт `r` из позы и зон |
| Приём телеметрии, логи, offline-метрики | Детект conspecifics сенсорами |
| Раздача **условий** до/в начале эпизода | Выбор действия и cmd в sport/nav |

### 1.3 Connectome is real data

Стартовая проводка — из FlyWire/Codex (snapshot, например FAFB v783), не random «fly-inspired» матрица.
Допустимо сжатие subgraph; недопустимо подменять топологию произвольным MLP без ablation-контроля.

## 2. Границы ответственности

```
arena_pc                         go2_i
────────                         ─────
zones, stimuli, safety    →      load episode conditions
episode start/stop        →      run local loop
                          ←      telemetry (observe only)
analyze logs offline             perceive peers locally
                                 update own weights
                                 publish actions to legs
```

**Запрещено** считать социальный эффект доказанным, если он зависит от сетевых сообщений о состоянии других агентов.

## 3. Интерфейс конфига эпизода

Конфиг эпизода — единственный «управляющий» объект, который PC передаёт особям как **условия мира**. После `episode_start` особь работает автономно до `episode_stop` / e-stop.

### 3.1 Транспорт

- Канал: ROS2 / DDS / UDP JSON — на усмотрение реализации.
- Топик (логический): `/arena/set_config` затем `/arena/episode/start`.
- Сообщение должно содержать `config_hash` (SHA-256 канонического YAML/JSON).
- Особь **отклоняет** старт, если hash не совпал с локально принятым конфигом.

### 3.2 Поля конфига

См. `configs/examples/episode.schema.yaml`. Обязательные группы:

| Группа | Назначение |
|---|---|
| `episode` | id, mode, duration, seed |
| `connectome` | artifact + FlyWire snapshot citation |
| `arena.zones` | полигоны и значения `r` среды |
| `arena.stimuli` | метки A/B, освещение/теги |
| `agents` | id, AprilTag, стартовая поза |
| `safety` | max_speed, fence, clearance |
| `analysis` | какие метрики писать (для PC) |

`mode` влияет только на **условия и локальные флаги**, не на серверный social coaching:

- `solo` — один агент;
- `multi_independent` — несколько агентов; детект conspecifics включён;
- `multi_blind_peers` — агенты физически есть, но локальный детект conspecifics выключен (контроль);
- `ablation_random_wiring` — тот же размер сети, random graph (контроль «это не муха»).

### 3.3 Что конфиг НЕ содержит

- чужие награды / MBON / веса других агентов;
- live-подсказки Avoid/Approach;
- shared_brain / average_weights;
- список «заразить агента X событием агента Y».

## 4. Локальный расчёт награды `r`

### 4.1 Источник истины

После загрузки `arena.zones` особь считает `r` **сама** из своей позы и локальной копии зон.

PC **не** публикует `/arena/reward/go2_i` как обучающий сигнал.
Допустимо, чтобы PC **параллельно** считал `r` только для логов и сверки (analysis mirror), но робот не должен от этого зависеть.

### 4.2 Алгоритм (нормативный)

На каждом тике MB (`f_mb`, по умолчанию 10 Hz):

```text
pose ← local odometry (map frame)
r ← 0
for zone in zones:
  if point_in_polygon(pose.xy, zone.polygon):
    r ← r + zone.reward          # обычно -1 для A, +1 для B
r ← clip(r, r_min, r_max)

# опциональные локальные aversive от собственного тела
if local_collision_event: r ← r + r_collision   # e.g. -0.5
if local_fall_event:      r ← r + r_fall

dan_channel ← 
  aversive  if r < 0
  appetitive if r > 0
  none       otherwise
```

Пластичность:

```text
update W_kc_mbon ONLY where M_dan_mask[dan_channel] == 1
η from connectome runtime config (локально)
```

Соседи **не** добавляют `r` через сеть. Вид соседа — это cue в `u_pn`, не чужой reward.

### 4.3 Карта зон

- Frame: `map` / `arena`.
- Полигоны: список вершин `[[x,y], ...]` в метрах.
- При конфликте зон (перекрытие) — суммирование `reward` с clip (явное в конфиге).

## 5. Запрещённые серверные сигналы

Любая реализация, шлющая нижеперечисленное **в контур обучения особи**, нарушает спецификацию.

### 5.1 Жёсткий запрет (MUST NOT)

| Сигнал | Почему нельзя |
|---|---|
| Чужой `r` / `punished` / `rewarded` | Внешний учитель социальности |
| Чужой `action` / `mbon_scores` / `W_out` | Телепатия вместо сенсоров |
| `boost_avoid(cue)` / `social_eta` с PC | Сервер формирует поведение |
| `shared_weights` / federated average online | Социальность вне индивида |
| Peer-to-peer learning messages | То же, минуя PC |
| Live переразметка ценности зон от поведения соседей | Скрытый social reward shaping |

### 5.2 Разрешено снаружи

| Сигнал | Зачем |
|---|---|
| `set_config` + `config_hash` | Условия эпизода |
| `episode_start` / `episode_stop` | Границы опыта |
| `e_stop` / safety limit updates | Безопасность |
| One-way telemetry ingest | Анализ |
| Offline batch jobs на логах | Метрики, графики, ablation |

### 5.3 Серая зона (нужно явно документировать)

- Синхронизация часов (NTP) — ок.
- Раздача одного и того же стартового `connectome_mb_v1.npz` до эпизода — ок (общая *донорская* проводка ≠ внешнее соцповедение).
- Смена зон **между** эпизодами — ок; смена зон mid-episode только как объявленный stimulus protocol, одинаковый для всех, без зависимости от особей.

### 5.4 Тест соответствия

Автоматический или ручной audit:

1. Отключить Wi‑Fi у робота после `episode_start` (кроме локального safety radio, если нужен e-stop).
2. Особь должна продолжать считать `r`, детектить видимых соседей и обновлять веса.
3. Если обучение без линка деградирует до нуля — архитектура не compliant.

E-stop может оставаться на отдельном канале; это не канал обучения.

## 6. Локальное восприятие сородичей

Социальные входы по-прежнему только из onboard perception. Сеть не передаёт ярлык «это собака». Три режима сенсора, все локальные:

### 6.1 `percept: fixed` — контроль с готовым детектором

| Cue | Сенсор | PN-маппинг |
|---|---|---|
| `conspecific_visible` | камера + AprilTag/детектор | фиксированный sparse PN-паттерн |
| `conspecific_near` | лидар distance < d_near | threat/spacing PN-пул |
| `conspecific_at_zone_B_seen` | камера: tag в ROI зоны B | отдельный PN-паттерн |
| `looming_conspecific` | быстрый рост bbox / closing lidar | aversive-biased cue |

Это не обучение узнавать собаку: класс уже подписан на входе.

### 6.2 `percept: raw` — узнавание из сырых признаков

AprilTag и канал `conspecific_*` выключены. Вместо них особь получает эгоцентрические признаки без имени класса:

- грубая камера (секторы обзора, цвет пола и тел, движение);
- лидар (близость и скорость сближения по секторам);
- отвлекающие объекты другого размера и скорости, которые не являются собаками.

Вектор проецируется **фиксированной случайной разреженной** картой на слой PN этой особи и дальше идёт обычным путём PN→KC→MBON. Пластичность по-прежнему только от собственного `r` зон (A = −1, B = +1) через DAN-маски KC→MBON. Чужие награды и веса не приходят.

Распознать другую собаку здесь можно только если её сырой паттерн систематически совпадает с собственным `r` и отделяется в KC от дистракторов. Это слабый учитель: вне зоны пластичности нет, а внутри зоны доминирует запах зоны. Отсутствие эффекта — допустимый результат, не повод подмешивать детектор.

### 6.3 Слепой контроль

Флаг `agents[].sense_conspecifics: false` (`multi_blind_peers`) локально убирает других собак: в `fixed` обнуляет peer-каналы, в `raw` и `recognize` не рисует их в камере и лидаре. Дистракторы остаются, чтобы контроль по-прежнему видел движение.

### 6.4 `percept: recognize` — слой узнавания сородичей

Между сырым вектором камеры/лидара и входом PN стоит отдельный слой. Его единственная работа — научиться отличать другую собаку. Он не читает награду зоны `r` и не получает ярлык класса ни по сети, ни из конфига эпизода. У каждой особи свой экземпляр, и он учится только на её собственном сенсоре.

Самообучение, без учителя:

- блобы вырезаются по секторам обзора; медиана цвета пола вычитается, чтобы заливка зоны не склеивала весь кадр в один объект;
- ворота самоподобия сравнивают угловой размер блоба с шириной собственного тела и оценку его скорости с проприоцептивной скоростью ходьбы; стояние на месте приор походки не обновляет;
- конкурентный Хебб: блоб, прошедший ворота, сдвигает прототип «сородич»; блоб, ворота не прошедший, сдвигает прототип «прочее»;
- если тот же азимут и похожий дескриптор держатся от кадра к кадру, шаг обновления больше (временная когерентность).

Пока прототип сородича ещё не собран (меньше четырёх обновлений), на выход идёт само ворота. После этого выход — косинус дескриптора блоба с выученным прототипом. Скаляр likeness умножает тот же разреженный PN-паттерн, которым в режиме `fixed` пользовался готовый детектор `conspecific_visible`, и прибавляется к проекции сырых признаков. Что делать при этом сигнале, по-прежнему учит обычная пластичность KC→MBON от собственного `r`.

Цвет в дескриптор не входит: окраска агентов разная, и прототип по цвету не перенёсся бы на другую особь. В дескрипторе — какая строка кадра зажглась (тело или пол), движение, близость, ширина и сближение.

Офлайн-пробник (ярлыки только в метрике, не в обучении) считает отклик на собаку против движущегося дистрактора, против неподвижного, и инвариантность: остановившаяся собака минус быстрый маленький объект. Пока выход равен воротам скорости, инвариантность отрицательная. Рост инвариантности и есть признак, что слой выучил внешний вид, а не мгновенную скорость.

### 6.5 Тренировка узнавания без зон

Отдельный режим, не эпизод с зонами. Одна обучаемая особь. Остальные собаки — только то, что она видит. Полигонов зон нет, награды `r` нет.

По умолчанию учится грибовидное тело этой особи. Сырой вектор камеры и лидара идёт фиксированной случайной проекцией на PN, дальше по коннектому PN → KC → MBON. Меняются только веса KC→MBON, и только когда приходит DAN. Другие особи своих весов сюда не присылают.

DAN по умолчанию — оператор на месте (`--dan teacher`). Клавиша `T` и кнопка TREAT вливают аппетитивный PAM. `X` вливает аверсивный PPL1. Это решение человека, который стоит рядом, а не подпись от другой особи и не канал сети. Стрелки вождения — только движение; `T` в них не входит. Каждая подача PAM или PPL1 рисуется меткой на шкале DAN монитора. Клавиша `G` открывает панель вспышки этого же шага и не шлёт движение. На ней загорается PAM или PPL1, точками отмечены KC, активные в кадр, и линиями — только синапсы KC→MBON, у которых вес изменился. Толщина — модуль Δw. Зелёный — сдвиг к подходу, красный — к избеганию. Около 1,5 с линии яркие, затем тускнеют. На панели число синапсов, сумма |Δw| и сырой выход MBON на этом кадре до и после. Координат xyz в коннектоме нет: точки стоят по root id и типам клеток, KC — по долям γ, αβ и α′β′. Панель в пластичность и в узнавание ничего не пишет.

Второй DAN, `--dan familiarity`: KC, которые уже срабатывали, ослабляют синапсы на MBON, стоящие на аверсивной маске. След занятости читается до обновления, так что первый взгляд не ослабляет. Тихий выход этих MBON — знакомство с частым паттерном. Это не признак «это собака»: разделение появляется, только если сородич виден чаще дистрактора, и общие KC переносят ослабление на другие виды.

Слой из §6.4 остаётся сравнением и включается флагом `--learner hebb`. В режиме по умолчанию он не учится.

`D` (собака в кадре) и `N` (нет собаки) только выбирают кривую на мониторе и копят панель точности. В проекцию, в `readout`, в калибровку уверенности и в пластичность они не передаются. Метка держится, пока не нажата другая.

Индикатор на мониторе — «УЗНАЮ СОРОДИЧА» или «НЕ УЗНАЮ» и уверенность 0–100%. Сырой выход MBON (подход минус избегание, числа вроде −350…+900) остаётся мелкой подписью: у него нет нуля «не собака», потому что смещение задаёт коннектом.

Уверенность считается так. Берётся окно последних 200 кадров. Энергия кадра — среднее модуля 72-мерного вектора камеры и лидара. Тихие кадры — энергия не выше 35-го перцентиля окна, занятые — не ниже 65-го. Это деление сенсора, не клавиша N. `пол` — медиана сырого выхода на тихих кадрах, `верх` — медиана на занятых. Пока `верх − пол` не больше двух MAD тихих кадров, индикатор «НЕ УЗНАЮ» и уверенность 0: у необученного мозга занятый кадр не вылезает из дрожания тихого. Когда разница уже есть, `z = (выход − пол) / (верх − пол)`. Уверенность — `z` в процентах, обрезанная к 0–100: 0% на тихом уровне, 100% на уровне занятых кадров. «УЗНАЮ СОРОДИЧА» включается при `z ≥ 0.8` и гаснет при `z < 0.65`. Пока в окне меньше 20 кадров, индикатор тоже «НЕ УЗНАЮ». Клавиши D, N, T и X в формулу не входят. Если энергия кадров почти одинаковая, верх и пол совпадают и индикатор узнавание не утверждает.

Метка сородича на карте лидара — тот же выход KC→MBON, не отдельный детектор. Полный кадр по-прежнему решает «УЗНАЮ СОРОДИЧА». Пока слово включено, тот же мозг с теми же весами, без пластичности и без записи в окно уверенности, читается ещё на восьми горизонтальных окнах по три сектора из восьми (обзор 110°, сектор 0 справа, положительный угол влево). На карту попадает окно с самым высоким сырым выходом, и ещё до двух соседних, если они почти так же высоки. Процент на метке — этот выход через тот же `пол` и `верх`, что и слово на полном кадре. Окно из одного сектора не лучше случайного выбора: его кроп не тот паттерн, с которым спаривали PAM. Окно из трёх секторов на двух из трёх семян (25 с, автолакомство, кадры после 8 с, где слово уже включено) попадало в сектор собаки или в соседний примерно в 70% таких кадров; на слабо разделённом семени метка смотрела мимо. Процент окна может быть высоким и на соседнем секторе. Метка гаснет за 2,5 с, если этот пеленг больше не лучший. Дальность берётся из канала «близко» лидара; если возврата нет, рисуется конус пеленга, а не точка.

Панель «насколько обучен» показывает время этой сессии и всего (пока обучение не на паузе), число лакомств PAM и наказаний PPL1, а при наличии меток D/N — разделение (средний сырой выход на D минус средний на N) и долю кадров, где индикатор совпал с меткой. Счётчики «всего» лежат в том же `logs/mb_train_state.npz`, что и веса. Новый запуск подхватывает файл, если он уже есть; `--load` при отсутствующем файле пишет в журнал «старт с нуля» и не падает. Клавиша R сбрасывает веса и эти счётчики вместе. Клавиша B включает короткий звук на переходе в «УЗНАЮ»; по умолчанию звук выключен. Если аудиоустройства нет, окно не падает, в панели будет «звук недоступен».

Монитор показывает камеру, карту лидара, выход MBON (для teacher это approach − avoid, для familiarity это минус выход MBON новизны), кривые «собака в кадре» и «нет собаки», дрейф `||W − W0||` по KC→MBON, полосу активности KC и шкалу DAN. Веса пишутся в `logs/mb_train_state.npz` (веса, след знакомства, семя проекции, имя DAN).

Поиск сородича — тот же выход KC→MBON и та же уверенность. Грибовидное тело и обучение здесь не меняются. Пока слово не удержалось, собака только поворачивается на месте в одну сторону: по умолчанию `z = +0.35` (влево) около 1,1 с, пауза 0,45 с, снова в ту же сторону, `x = 0`. После выхода из «доворот» или «подтверждено — иду» в поиск знак берётся по последнему наблюдению (R_L−R_R или глаз, который узнавал последним; при нулевой разнице остаётся прежняя сторона) и не меняется, пока поиск идёт. Память стороны 10 с, дальше снова влево. На экране «поиск ←» или «поиск →». Прежняя качка `±0.35` была этим контроллером, не мозгом: знак `z` меняла функция поиска. В режиме секторов подход начинается после 5 из последних 8 кадров со словом «УЗНАЮ». Сектор для поворота — медиана последних 5 сырых секторов мозга (`sector_smooth`). Сырой `sector` в статусе остаётся сильнейшим окном этого кадра и может прыгать 0→6→1: это дрожание пеленга мозга. Если медиана тоже гуляет между краями, устойчивого пеленга в окне нет — это по-прежнему мозг, контроллер только перестаёт дёргать `z` на каждом кадре. После пропажи слова цель держится ещё 1 с. Сектор 0 — правый край поля 110°, сектор 7 — левый, влево это `z > 0`. Секторы 3 и 4 — прямо по курсу: внутри половины сектора `z = 0` и `x = 0.4`. Дальше от центра поворот пропорционален углу, и при большом угле `x` около 0,2, а не разворот на месте.

Дальность сектора — 10-й перцентиль точек дальше `--self-radius` (по умолчанию 0,6 м) и вне корпуса. Ближний минимум около 0,35 м — ноги и крепление, его больше нет в `distance_m` и `forward_m`. Если надёжной дальности нет, собака идёт медленно (`x` около 0,2) и встаёт, когда препятствие впереди, уже за радиусом тела, ближе 1 м. Эти две дальности написаны на мониторе. Каждый `Move` зажат: `x` в диапазоне [−0,4, 0,4], `z` в диапазоне [−1, 1], `y = 0`.

Два грибовидных тела, MB_L и MB_R, сидят на одном коннектоме и держат свои веса KC→MBON. Вход — тот же 72-мерный вектор. По умолчанию `--recog-camera-only`: перед PN→KC обнуляются лидарные каналы (близость и сближение), в обоих полушариях, в обучении KC→MBON, в R_L/R_R и в секторах map_marks. Лидар остаётся для дальности, стопа ближе 1 м, препятствий и карты. `--no-recog-camera-only` возвращает эти каналы во вход. Формат `mb_train_state.npz` от этого не меняется. Старые веса загружаются, но они учились с лидаром в векторе: для узнавания только по камере нужен сброс `R`. При `--overlap 0` MB_L видит секторы 4–7 (лево робота, `z > 0`), MB_R — секторы 0–3, зеркально записанные в те же слоты 4–7. По умолчанию `--overlap 0.4`: общая полоса 40% ширины поля, MB_L берёт долю [0.30, 1], MB_R — [0, 0.70], и каждая доля снова укладывается в четыре слота 4–7. Размер входа и набор массивов в `mb_train_state.npz` от этого не меняются. Сектор 0 — правый край поля и одновременно левые столбцы кадра превью: индекс общий у камеры и лидара. Резать JPEG по пиксельному левому краю значило бы отдать MB_L правые бины лидара. Проекция на PN одна, семя прежнее: одинаковый узор слева и справа попадает в одни клубочки, иначе скопированные веса узнавали бы собаку только с той стороны, где их учили. Общее слово «УЗНАЮ» по-прежнему считается по сумме двух выходов. У каждого полушария свой калибратор, те же пороги 0.80 и 0.65, и в `/status` лежат `recognized_L`, `recognized_R`, `confidence_L`, `confidence_R` и `overlap`.

В режиме `bilateral` вперёд идёт только подтверждение вторым глазом. Оба полушария узнали — `x = 0.4` и `z = (R_L − R_R) / (|R_L| + |R_R| + ε)`, мёртвая зона 0.08, даже если разница большая. Ближе 1 м по-прежнему стоп. Узнало одно — доворот на месте, `x = 0`, `z = ±0.35` в его сторону. Если второй глаз молчит 3 с, это ложная тревога и снова поиск в одну сторону, пока этот глаз не погаснет. Если на ходу один глаз погас на 5 кадров, снова доворот. Фазы: «поиск ←» или «поиск →», «доворот (Л)», «доворот (П)», «подтверждено — иду», плюс «стоп 1 м», «ручное», «стоп». Сглаживание суммы — EMA на контроллере, не в весах. Режим `sectors` оставляет прежний пеленг по медиане сектора. Клавиша `K` и кнопка переключают режим, то же `--steer sectors|bilateral`. `Y` включает и выключает авто-учителя (подкрепления, не ход). `H` прячет рамки YOLO, пока включено обучение. `F11` — полный экран. `T` и `X` кормят обе половины сразу. Старый файл с одним массивом `kc_mbon_w` копируется в обе половины; новый файл пишет ещё `kc_mbon_w_r` и `kc_fam_r`, без object-массивов. На мониторе строка «узнавание: только камера», строка `муха L … R … Δ … z` и крупная строка `R_L … R_R …` со словами «ОБА ВИДЯТ → ИДУ», «ОДИН ГЛАЗ → ДОВОРОТ» или «НЕТ → ПОИСК». На кадре общая зона голубая, две границы, подписи Л, Л+П, П и процент перекрытия. Над левой половиной кадра плашка «П: УЗНАЮ» или «П: —», над правой «Л: УЗНАЮ» или «Л: —»: зелёная, когда этот глаз узнал, иначе серая. Это только экран: в JPEG записи кадр не красится.

Запись кадров для будущего YOLO — лог ноутбука, не ход и не обучение. `U` и «ЗАПИСЬ КАДРОВ» кладут JPEG в `logs/yolo_frames/` только когда за последние 0,5 с оператор нажал T/D или X/N. Кадр без этой метки не пишется. В режимах робота и `--onboard` байты берутся с `:8088/camera.jpg` на ноутбуке. Робот файлы не пишет, превью-сервер не меняется. Рядом JSON со слабой меткой оператора (T/D — dog, X/N — no_dog за 0,5 с), выходом MB и скоростью. Пакеты YOLO остаются в `tools/yolo_teacher` и в exe тренажёра не входят.

Клавиша `A` и кнопка «СТАРТ АВТО» включают и выключают этот ход. Пока автономия выключена, в симуляторе отпущенные стрелки по-прежнему ведут ученика сценарием между собаками и дистрактором, а на живой собаке отпущенные стрелки шлют `StopMove`. `P` отдельно включает и выключает обучение. При выключенном обучении `T` и `X` веса не меняют, журнал пишет «обучение выключено, T/X веса не меняют», а поиск может идти. Удержание `T` или `X` повторяет DAN примерно раз в 0,45 с.

Стрелки во время автономии собаку не забирают и `Move` от себя не шлют. На экране подсказка «нажми ПЕРЕХВАТ». Перехват — клавиша `M` и кнопка «ПЕРЕХВАТ». Если борт сам слал `Move`, перехват один раз шлёт `StopMove`; если хода от борта не было, `SportClient` молчит. Режим становится ручным, и только тогда стрелки ведут, с теми же пределами `x` и `z`. Окно `--onboard` в том же кадре, что и ответ `M`, берёт свежий статус (`took_over` и `mode=manual`) и сразу шлёт `op=manual`, не дожидаясь следующего опроса. Обратно в автономию — снова `A`. Сама она не возвращается. `--return-auto SEC` может вернуть её после простоя, по умолчанию 0. Если после перехвата ручные оси молчат дольше 0,3 с и борт успел послать `Move`, один `StopMove`, режим остаётся ручным. Ручной `Move` пишется в журнал борта не чаще раза в секунду, строкой `Move x=… z=… code=…`: `code` — ответ `SportClient.Move`. `T` и `X` в ручном режиме учат, пока обучение включено.

`Space` останавливает в любом режиме и снимает автономию: чтобы ехать самой, снова нужна `A`. `StopMove` при этом один, и только если борт сам слал `Move`. `E` и кнопка E-STOP выше всего: один `StopMove` и блок, повтор в том же блоке команд не шлёт. `A` автономию не включает, выход в ручное — `M`. Потеря фокуса окна на ноутбуке с UDP шлёт `StopMove` и флаг автономии не стирает. На борту пропажа кадров или тишина ноутбука дольше 1 с даёт один `StopMove` только если перед этим борт сам слал `Move`. Наблюдение (автономия выключена, перехвата нет) `SportClient` не вызывает: ни `Move`, ни `StopMove`. `+` / «ВСТАТЬ» — `StandUp`, затем через 0,7 с `BalanceStand`. Этот шаг делает `tick`, HTTP и цикл не спят. В SDK `StandUp` запирает суставы, и `Move` после него не идёт, пока нет `BalanceStand`. Если к первому `Move` после перехвата или старта автономии замок ещё не снят, `BalanceStand` уходит один раз прямо перед этим `Move` и второй раз по таймеру уже не повторяется. `-` / «ЛЕЧЬ» — `StandDown` и снимает ожидание `BalanceStand`. «ПОДЪЁМ» — `RecoveryStand`. Всё это только по явной команде.

Крупная строка на мониторе: «АВТОНОМИЯ», «РУЧНОЕ · ПЕРЕХВАТ», «РУЧНОЕ» или «СТОП», и кто ведёт сейчас: мозг, оператор или никто.

На ноутбуке команды по-прежнему UDP JSON на `127.0.0.1:5451` (`Move` / `StopMove` примерно каждые 100 мс). `x` этого тренажёра теперь ±0,4, не прежние ±0,5. `--onboard 192.168.35.213` мозг на ноутбуке не считает и на 5451 ничего не шлёт: окно показывает камеру и лидар с порта 8088, статус, стойка и кнопки уходят на порт 8090 робота. Окно не зависит от `python main.py`. Если мост всё же слушает UDP 5451, на экране написано, что это два источника команд.

Бортовая копия — `robot/flybrain_onboard/`, на собаке каталог `/root/flybrain/`. Камера и лидар читаются с уже работающего превью `http://127.0.0.1:8088`. Второй `VideoClient` не открывается. Дальность для остановки около 1 м по возможности берётся из облака `rt/utlidar/cloud_deskewed` только на чтение; если его нет, остаётся дальность по JPEG. Ходьба — `SportClient.Move` / `StopMove`. После `StandUp` суставы заперты, пока `tick` не пошлёт `BalanceStand` (через 0,7 с или один раз перед первым `Move`). `Damp` и `SwitchJoystick` этот процесс не вызывает. После старта автономия и обучение выключены. Коннектом на собаке — `connectome_mb_v1_np1.npz` (строки как `<U`, без pickle). `deploy_flybrain.py start` без флагов оставляет `/root/flybrain/state/mb_train_state.npz` на собаке. `--state PATH` подменяет этот файл. Стереть его может только `--clean`. Выкладка вручную: `python robot/deploy_flybrain.py start|stop|status`, пароль только из `GO2_SSH_PASS`. Юнит systemd превью скрипт не трогает и в автозапуск мозг не ставит.

Пульт Unitree этим приложением не подменяется. `Move` спорт-сервис держит около секунды, поэтому оборвавшийся отправитель ещё катится, пока не придёт `StopMove` или не выйдет эта секунда. `SwitchJoystick` в SDK есть и менял бы поведение пульта, поэтому отсюда он не вызывается. `ObstaclesAvoidClient.UseRemoteCommandFromApi` — другой клиент, вместе со `SportClient` его не включают. В описании `SportClient` нет переключателя «пульт всегда важнее Move». На пульт как на перехват этого окна полагаться не стоит: перехват — `M`, стоп — E-STOP. Если пульт и `Move` активны вместе, они могут спорить. Отпускание стика само по себе ручной режим нашего процесса не включает и автономию не гасит.

Камера и карта лидара читаются по HTTP с уже существующего превью (`http://<robot_ip>:8088/camera.jpg` и `lidar.jpg`, IP по умолчанию `192.168.35.213`) и переводятся в тот же 72-мерный вектор, что и симулятор. По умолчанию `--lidar-refresh 1.5`: тренажёр сам делает `GET /lidar/reset` раз в полторы секунды и отдаёт мозгу последний полный кадр перед следующим сбросом. Первые 0,45 с после сброса карта ещё пустая, эти кадры в KC→MBON не идут. На экране держится тот же полный кадр, без мигания. `V` или `--lidar-refresh 0` возвращают накопление. Кнопка «СБРОС ЛИДАРА» и клавиша `C` по-прежнему делают один `GET /lidar/reset` и пишут в журнал, дошло или нет. Если загруженные веса учились на другом режиме лидара, журнал предлагает `R` и файл не стирает. Старый `npz` без поля `lidar_refresh` загружается: это накопленная карта. В симуляторе та же клавиша стирает накопленный след точек; текущие тела рисуются снова. Старый сервер превью отдаёт только JPEG: робот на нём не в центре кадра (линейка слева и снизу, оси мира, нос по курсу), поэтому без геометрии конус строится так, будто робот в центре и нос вверх, и может сесть мимо возврата. `robot/robot_preview_server_v2.py` сохраняет те же три адреса и добавляет `GET /lidar/scan.json` (пиксель робота, курс, метры на пиксель, дальность по восьми секторам). Тренажёр берёт оттуда точку на карте, а если JSON нет — остаётся конус. Как выложить v2 на собаку — в `docs/fly_go2/simulator.md`. Headless-прогон симулятора сам нажимает `T`, когда в кадре только другая собака: это глаза оператора для отчёта, а не ярлык внутри вектора признаков. Числа этого прогона — в `docs/fly_go2/mb_train_results.md`.

## 7. Анализ результатов на PC

PC подписан на телеметрию и пишет `episode_id/` лог. Обучение не корректирует.

### 7.1 Обязательные метрики (per agent)

| Метрика | Определение |
|---|---|
| `PI` | `(t_B - t_A) / (t_A + t_B + eps)` за эпизод или окна |
| `time_in_A`, `time_in_B` | секунды в зонах |
| `n_zone_entries` | число входов в A/B |
| `mean_|r|`, `n_plastic_updates` | активность учителя |
| `action_hist` | доля MBON-действий |
| `weight_drift` | `||W_t - W_0||` по masked синапсам |
| `peer_exposure_s` | время с `conspecific_visible` |
| `distance_to_nearest_peer` | распределение |

### 7.2 Популяционные / социальные метрики (post-hoc)

Считаются **только из логов**, не вмешиваются в рантайм:

| Метрика | Смысл |
|---|---|
| `aggregation_index` | скученность относительно random null |
| `avoidance_contagion` | ускорение Avoid_A у особи после *видимого* контакта с особью, часто бывавшей в A (по локальным флагам `*_seen`, не по Wi‑Fi) |
| `blind_vs_sighted_delta` | разница PI / spacing между `multi_independent` и `multi_blind_peers` |
| `flywire_vs_random` | то же для connectome vs `ablation_random_wiring` |
| `individuality` | дисперсия `W` и политик между агентами с одной стартовой проводкой |

Социальный эффект засчитывается **только если** `blind_vs_sighted_delta` значим в пользу sighted при прочих равных условиях арены.

`summary.json` обязан содержать `connectome.manifest_id`, `config_hash`, `mode`, список agent ids.

## 10. Краткая формула

> Внешнее задаёт мир и пишет логи.  
> Коннектом + пластичность + восприятие сородичей — только в индивиде.  
> Социальное поведение = выученная особью реакция на сенсорно доступных агентов.
